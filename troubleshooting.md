# Устранение неисправностей

**Навигация:** [Главная](index.md) · [Быстрый старт](quick-start.md) · [Установка](installation.md) · [Руководство пользователя](user-guide.md) · [Справка](reference.md) · [Устранение неисправностей](troubleshooting.md) · [Источники](sources.md)

## Страница CyberChef не открывается

1. Проверьте, правильно ли введён адрес.
2. Для локального варианта убедитесь, что Docker-контейнер или сервер разработки запущен.
3. Проверьте, не занят ли порт `8080`.
4. Если это веб-версия, обновите страницу или попробуйте другой современный браузер.

Для Docker можно проверить запущенные контейнеры:

```bash
docker ps
```

Если контейнер присутствует в списке, но интерфейс недоступен, изучите журнал:

```bash
docker logs <имя_или_ID_контейнера>
```

## Не получается получить ожидаемый результат

- проверьте исходные данные;
- убедитесь, что выбрана правильная операция;
- проверьте параметры операции;
- проверьте порядок операций в Recipe;
- выполните пример из [быстрого старта](quick-start.md) для сравнения.

## Base64 не декодируется

Убедитесь, что в качестве входа передана строка Base64 без лишних символов, пробелов или текста пояснения. Для проверки используйте короткую тестовую строку из [руководства пользователя](user-guide.md).

## Локальная сборка не запускается

Проверьте версии инструментов:

```bash
node --version
npm --version
git --version
```

Убедитесь, что установлен Node.js 24, а `npm install` завершился без ошибок. Затем изучите вывод команды `npm start`. Порядок установки приведён в разделе [Установка и запуск](installation.md).

## Production-сборка завершается ошибкой

Запустите сборку ещё раз и сохраните полный текст ошибки:

```bash
npm run build
```

Если в сообщении указано, что закончилась память JavaScript heap, обратитесь к актуальному README официального проекта: в нём описан скрипт `npm run setheapsize`. Не меняйте настройки памяти, если причина ошибки другая.

## Внешняя операция не работает

Некоторые операции могут обращаться к внешним сервисам. Проверьте интернет-соединение, DNS, настройки прокси и ограничения межсетевого экрана. Не отключайте защитные средства ради обхода ошибки без разрешения администратора.

## Когда нужна эскалация

Обратитесь к преподавателю или системному администратору, если:
- ошибка повторяется после проверки входных данных и стандартных действий;
- требуется изменение системных настроек или сетевой политики;
- проблема связана с недоступностью внешнего сервиса;
- появились сообщения о подозрительном или несанкционированном изменении файлов.

При обращении укажите способ запуска, время ошибки, точный текст сообщения и действия, выполненные перед сбоем.
